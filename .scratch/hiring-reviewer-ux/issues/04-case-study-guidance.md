# Explain the evidence and starting Artifact in lead design Case Studies

## Parent

[Specification #23: Hiring-first evidence review and reliable portfolio browsing](https://github.com/daffaghiffarykusuma/dafghif-learning-portfolio/issues/23)

## What to build

A Hiring Reviewer opening Administrative Communication or Learning Organization Strategy can read a concise What this demonstrates summary and follow one suggested starting Artifact before deciding how deeply to inspect the remaining work. The guidance survives regeneration and accurately describes the evidence available.

Complete the source-to-generated-page-to-Artifact path through Portfolio Item Source, Case Study Publication, and Portfolio Evidence Workflow. Keep this as one slice across the two cases because they share the publication behavior. Any optional source extension and its validation belong inside this ticket, before the rendering change that consumes it.

## Acceptance criteria

- [ ] Both lead design cases show a short What this demonstrates summary and one clearly identified starting Artifact before the full Artifact collection.
- [ ] Each summary reuses or conservatively expresses explicit, supported source content, including existing Use case context where appropriate. The Reviewer can connect the artifacts to learning-design capability without a new impact claim.
- [ ] Each recommended starting action resolves to an existing Artifact and works through the existing preview or in-page Artifact navigation behavior. The action's wording accurately describes what it does.
- [ ] Editorial selection remains in Portfolio Item Source. If an optional selection field is necessary, validate that it refers to an Artifact in the same Case Study and preserve compatibility for unrelated cases.
- [ ] The guidance survives Portfolio Evidence Workflow regeneration; there is no hand-maintained duplicate summary store or manual-only edit to generated pages.
- [ ] Preserve all existing Artifact identities, source links, preview triggers, complete collections, source attribution, evidence-limit notes, and optional deeper design explanations.
- [ ] Do not infer personal ownership, client commissioning, delivery, adoption, or measured impact. Unconfirmed contribution details stay deferred rather than appearing as facts or invented placeholders in public copy.
- [ ] Administrative Communication's documented certification-assessment purpose may be described without claiming it was the only use or that its 36-hour design was delivered. Do not infer Learning Organization Strategy's purpose from filenames.
- [ ] Extend Portfolio Evidence Workflow output coverage for both cases, valid starting links, source agreement, regeneration, and unaffected unrelated cases. If the source schema changes, cover invalid references at the existing validation boundary.
- [ ] Inspect both generated pages and follow each starting action against the production preview at desktop and phone sizes, including keyboard access. Review the prose against the underlying evidence; automated strings do not establish truth.
- [ ] Existing type checks, automated tests, site validation, production build, performance guards, Proof Point attribution, metadata consistency, and Shipped Artifact Policy remain intact. Report generation tests and browser observations separately.

## Blocked by

None (can start immediately). Existing preview and publication interfaces support the guidance; this ticket does not depend on catalogue history, homepage, or contact changes. Deferred personal-contribution facts are outside its source-supported scope.
